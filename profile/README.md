<p>搜"住宅 IP 排名"，出来的多是清单体文章：谁第一、谁第二、各自几分。这类内容参考价值有限，因为你不知道评测的时间、线路、采样方式，也不知道作者测的是哪条节点。更实用的思路是把排名换成一次可复现的对照实验：固定机器、固定时段、固定脚本，让两家资源在同一条件下跑一遍，结论自己会浮出来。下面给出一套四组对照的做法。</p>

<h2>一、把"排名"换成可复现的实测，结论才站得住</h2>
<p>可复现的意思是：换个人、换一天，按同样的步骤还能得到相近的结果。做到这点需要三个固定——同一台测试机、同一时段、同一套命令。缺一个，结论就会被环境差异吃掉大半，尤其是延迟这类对线路敏感的数据。</p>
<p>还有一件事要先明确：你要测的是"这条线路适合你的用法吗"，不是"这条线路全世界排第几"。同一个节点，用来跑对话和用来跑批量请求，评价标准完全不同。所以实验开始前先写下一句话：我的主要用途是什么，能接受的底线是多少。</p>

<h2>二、实验设计：同一台机器、同一时段、同一套脚本</h2>
<p>设计成四组对照：延迟与抖动、丢包与掉线、出口纯净度、替换政策与响应。前三组靠技术手段测，第四组靠沟通记录。四组都做完，一份比排名更可信的评估就有了。</p>

<h2>三、第一组对照：延迟与抖动，别只看平均值</h2>
<img src="/tp.png" alt="两家住宅IP节点在延迟、抖动与丢包三项指标上的对照测试示意">
<p>平均值是最容易被包装的数字：只测一次、只挑空闲时段、只取最快的那几十个包，都能让平均值好看。真正反映体验的是抖动，也就是延迟的波动幅度。平均 150 毫秒、波动正负 20 毫秒，比平均 120 毫秒、波动正负 90 毫秒舒服得多。</p>
<h3>怎么把抖动读出来</h3>
<p>跑 <code>ping -c 100 目标域名</code>，看输出的 min、avg、max、mdev 四个值。mdev 除以 avg 得到的比值，超过 0.4 就说明波动偏大。这个比值比单看平均值更接近你实际感受到的"卡不卡"。</p>
<h3>三天连测的意义</h3>
<p>单日数据不能代表长期表现。连测三天，每天同一时段，看的是趋势：如果三天里有一天的延迟翻倍，说明这条线路存在时段性拥塞，不适合放在关键任务上。</p>

<h2>四、第二组对照：丢包与掉线，晚高峰才是分水岭</h2>
<p>丢包是最能区分线路质量的指标。平均值一样的两条线，一条白天零丢包、晚上丢百分之三，另一条全天稳定丢百分之零点五，前者体验会明显更差，因为丢包发生在你最需要用的时候。</p>
<p>测法上，用 <code>mtr</code> 跑一百包，重点看丢包从第几跳开始出现。全程零星丢，多是本地网络或无线干扰；某一跳之后连续丢，问题在那一段骨干；最后一跳才丢，多为目标侧限流，与你的出口关系不大。</p>
<h3>掉线要区分"断"和"慢"</h3>
<p>断是连接失效，需要重连；慢是延迟升高，连接还在。前者看日志里的重连次数，后者看响应时间的分布。把两者混为一谈，会误判成"线路很差"，实际上可能只是晚高峰带宽被挤。</p>

<h2>五、第三与第四组对照：纯净度、替换政策与响应时效</h2>
<p>纯净度不是玄学，可以拆成可查的三项：ASN 类型是否与宣传一致、同段 IP 的使用密度、公开信誉库里的记录。三项里前两项影响长期表现，第三项影响的是"接手时的起点"。</p>
<h3>同段使用密度怎么估</h3>
<p>没有直接接口，但可以用间接方法：连续查询同一 C 段内若干地址的响应特征，或者直接问服务商"这条 IP 同时分配给了几个客户"。正规服务商会给出明确口径，含糊其辞的往往意味着共享率不低。</p>
<h3>替换政策要问成具体数字</h3>
<p>不要问"能不能换"，要问：多久可以换一次、是否收费、换后是否保持同一城市、故障判定需要什么证据。四个问题问完，这项的真实价值就清楚了。故障频发的线路，替换政策宽松与否，直接影响你一个月要花多少时间在上面。</p>

<h2>常见问答</h2>
<h3>自己测和看别人评测，差在哪？</h3>
<p>答：差在变量可控。别人测的时段、机器、节点都不一定和你相同，尤其线路质量在晚高峰差异很大。自测的价值在于结论对你的环境成立，代价是要花几个小时。</p>
<h3>只测一次 ping 够不够？</h3>
<p>答：不够。单次 ping 只能说明那一刻的状态。至少连测三天、每天覆盖一个高峰时段，才能看出趋势。测一次就下结论，很容易被偶然的好数字误导。</p>
<h3>替换政策为什么也算评测项？</h3>
<p>答：因为它决定长期成本。一条线一年换三次、每次收费，累计支出可能超过贵一点的方案。把它折成"年化成本"和价格放在一起比，才公平。</p>
<h3>两家都不理想，是不是该换第三家？</h3>
<p>答：先确认失败原因是资源问题还是用法问题。如果两家都在晚高峰丢包，可能是你本地出口到该地区的公共链路拥塞，换第三家也未必改善，此时该考虑的是调整使用时段或加一条备用线。</p>
